# 0.27.2 Greenhouse QoL: implementation plan

Source: [0.27.2 Release Candidate, "► Greenhouse QOL"](https://hypixel.net/threads/september-30-0-27-2-release-candidate.6158219/) (September 30).
Hypixel marks these changes as experimental. We are still replacing the old rules outright: there is **no legacy-rules toggle**. If Hypixel changes the numbers, they go into `data.json` and the Advanced overrides.

Read the `greenhouse-simulator` skill first (`.claude/skills/greenhouse-simulator`). Its invariants still hold: one stepping path, determinism and splittability, state as plain data, fixed iteration order, and plots interacting only through shared inventory and aggregates.

## Confirmed rules (user-verified)

### Decay and the minimum mutation value

- Each crop or mutation kind has a **minimum mutation value**: an integer, **N/A** (no minimum) or **Infinite**. The values go in `data.json` as `minimum_mutations` (see Phase 0).
- **Every plant gets it.** That covers planted base crops, placed mutation items, natural spawns and Dead Plants. Each plant tracks two counters:
  - `timesMutated`, starting at 0.
  - `mutatesRemaining`, starting at the minimum. It can go **negative**. It is `null` for N/A and `"infinite"` for Magic Jellybean.
- **Credit**: when a mutation **spawns** (credited at that moment), each requirement `{crop, count}` of the new mutation credits that many cells' worth of neighbours of that kind in its 8-way ring:
  - Only up to the required count.
  - Each distinct plant is credited at most once per spawn.
  - A multi-cell neighbour counts its ring cells toward the requirement, the same as spawning does.
  - A credited plant gets `timesMutated += 1` and `mutatesRemaining -= 1`.
  - **Dried-out (halted) plants are not credited**, because they don't count toward requirements.
  - Mutations with no crop requirements (Godseed, Lonelily, Shellfruit made by a blast) credit nobody.
- **Which neighbours get credited** when there are more than needed is unpublished. The default is a fixed ring order (cell index ascending, row by row from the top-left), configurable as `mutationCreditOrder`.
- **Pool**: per plot, per kind. A plant is **pooled** iff `timesMutated ≥ 1` **and** it is fully grown (placed items count as fully grown). `combinedMutatesRemaining(kind)` = the sum of `mutatesRemaining` over that kind's pooled plants. It can be negative, and is infinite if any member is infinite. A new plant only joins once it has helped at least once and is fully grown, so whether it pulls the pool back above 0 depends on its own remaining count at that point.
- **Decay check** (game tick, `decay` phase). When a plant's timer reaches ≤ 0:
  - If the kind's minimum is N/A, it decays, as before.
  - If its minimum is Infinite, it never decays.
  - If it is pooled, it decays iff the pool is **≤ 0**. The pool is snapshotted **once per plot per tick** at the start of the phase, so every plant of the kind whose timer expires that tick goes together.
  - Otherwise it decays iff its own `mutatesRemaining ≤ 0`. A plant with `timesMutated = 0` therefore never decays.
  - If it doesn't decay, the timer is **extended by 24h** (`decayExtensionHours`), as many times as needed. If the minimum is met during an extension, the plant decays when that extension runs out.
- A kind with **no decay timer** never decays, whatever its minimum. This covers Fleshtrap (decay 0, minimum 6), Magic Jellybean, All-in Aloe, Fire and Fermento.
- **Base crops decay after 3 days** (72h), now stored in `data.json` as crop `decay: 3` (days). This replaces `baseCropDecayHours`.
- **Dead Plants**:
  - They decay after 3 days, with a minimum of 10.
  - When one decays it **leaves nothing**: the cell goes empty and the player re-places the layout's dead plant from inventory.
  - A Dead Plant left behind by decay gets a fresh timer and a minimum of 10. It has never helped anything, so it won't decay on its own; the player clears it at the next session, as today.
  - **Zombud farms (unchanged, `sim/zombud.ts`):** harvesting a Zombud still turns every Dead Plant in its ring into a Zombud mob. The fight is assumed won and each mob gives exactly 1 Zombud. Those Dead Plants are **consumed by the harvest, not decayed**, and the player re-places fresh ones from stock.
    - A Zombud spawn credits 4 of them, like any requirement. Each therefore helps at most once before the harvest consumes it, so it never reaches its minimum of 10 and never decays.
    - A consumed Dead Plant leaves the pool, taking its remaining count with it.
  - This replaces `nullStageKindsDecay`.
- **Fire and Fermento** never decay and have no minimum.
- The player's decay predictions (`spawnedHarvest: beforeDecay`, `baseCropUpkeep: harvestBeforeDecay`, the hybrid "save a kept input from decay" rule, the `decayImminent` trigger) use the **current** counters ("would decay if the timer ran out now"). A help that lands on the same tick can still surprise them; that is accepted.

### Water

- Reaching `haltWater` (−100, the old `deathWater`) now **halts** a plant instead of killing it. The existing chance to skip a stage below 0 water stays.
- A dried-out plant (`water ≤ haltWater`):
  - doesn't grow;
  - doesn't count toward any mutation's requirements (so it can't be credited);
  - **gives** no effects and doesn't relay them, though it still receives them;
  - doesn't count toward the unique crop bonus;
  - **still blocks Lonelily** (it is physically there);
  - keeps running down its decay timer.
- Watering at the next session un-halts it. Only plants that consume water can reach the threshold, so the halt can be derived from `water`.
- **Water loss (user-confirmed follow-up, Phase 2b):**
  - A water consumer loses `waterLossMin..waterLossMax` (default **18–22**, × retain/drain factor) **every cycle while it is not fully grown**, whether or not it advanced that cycle (gated, skipped or blocked cycles still drain). It stops losing water once fully grown. A dried-out plant loses no more water (it is already halted).
  - **Spawned mutations start at 0 water** (every spawn; placed items and planted crops are unchanged).
- **Uptime:** a dried-out target mutation standing on its own watched slot is recorded as a new **`halted`** status. It counts as downtime (uptime = (growing + ready) / watched), is reported separately, and does **not** by itself mark the run unsustainable (only `requirements` does).

### Special mutations

- **PlantBoy Advance and Stoplight Petal**: a failed minigame (only possible when Perfect minigames is off) leaves the plant at the same stage, still fully grown, and the player tries again at the next session. On a step change or a blocked layout cell (`removeByPlayer`), a failed harvest still breaks it. **Phantomleaf** is unchanged: a fail destroys it.
- **Thunderling**:
  - It starts with 0 charge when it spawns and gains **+2000 per stage grown**.
  - At **≥ 16,000** charge it stops growing (a growth stop only, like a sleeping Snoozling: it still counts for requirements and still shares effect_spread). It gains no charge above 16,000.
  - The player discharges it each session (new `gateInteractions.dischargeThunderling`, default on).
  - Placed Thunderlings don't grow, so they build no charge.

### Unique crop bonus

- It is linear: **+2.5% growth speed and +2.5% yield per unique crop**, capped at **10** crops (25% / 25%). Sunflower/moonflower and the two mushrooms still count as one each.
- **Flora** (new player stat, 0 to 10, **default 10**) adds to the count, and the total is still capped at 10. With the default, every scenario gets the full bonus whatever base crops are standing.

### Out of scope

The Carpenter's Crop Guide drop rates and Flora being obtainable from analyzing Mutations are in-game UI only, so they need no site change.

## Phase 3: decay rework (minimum mutations, pools, extensions, Dead Plant decay)

The largest phase. It depends on Phases 0 and 2. Sub-steps 3a to 3e change the engine; 3f is config and UI; 3g is tests. Land the engine and the tests together.

### 3a. Timers from data

- `sim/plants.ts` `initialDecaySeconds`: crops use `CropDef.decayDays` (0 = never). `decayDaysOverrides` now applies to **any kind**, crops included.
- Remove `baseCropDecayHours` and `nullStageKindsDecay` from `SimConfig`, `DEFAULT_CONFIG` and `CONFIG_META`. Add a migration in `migrate.ts`:
  - `baseCropDecayHours` ≠ 72 becomes `decayDaysOverrides` for the 14 base crops (hours / 24; 0 stays 0), unless the crop is already overridden.
  - Drop `nullStageKindsDecay`.
  - Add tests in `scenarioEdit.test.ts`.
- `convertToDeadPlant` gives the new Dead Plant the `dead_plant` timer and counters, instead of `null`.

### 3b. Plant counters

- `PlantState` gets two new top-level fields:
  - `timesMutated: number`
  - `mutatesRemaining: number | "infinite" | null`
- Initialise them in `newPlant` (from `minimumMutationsOf(kind, config)`, with overrides applied), in `newRoot` (`0` / `null`) and in `convertToDeadPlant`. The Shellfruit made by `turtleIntoShellfruit` gets fresh counters.

### 3c. Crediting (new `sim/decay.ts`)

- `creditInputs(plot, occ, spawned, mutation, config, rng)` is called in `phaseSpawn` right after a spawn is inserted.
- It walks `ringCells(row, col, size)` per requirement. It skips dry plants and counts cells until `count` is reached, crediting each distinct plant once.
- Order comes from `config.mutationCreditOrder`:
  - `ringOrder` (default, no RNG)
  - `mostRemainingFirst` (spreads use evenly)
  - `fewestRemainingFirst` (uses up the same ones)
  - `random` (draws RNG only when selected)
- Earlier same-tick spawns count, exactly as for requirements.
- No event is emitted: it would be too noisy. The tooltip shows the counters.

### 3d. Decay phase

- `phaseDecay`:
  1. Snapshot `combinedByKind(plot)` (a local Map, never stored).
  2. For each plant with a timer: count it down.
  3. If it expired, check `minimumMet(p, snapshot)`. If met, it decays. If not, add 24h until the timer is positive again, emit **`decayExtended`** `{plantId, kindId, row, col, remaining, combined}` and bump `summary.extended[kind]`.
- Decay of a `dead_plant`-kind plant (layout-placed or left behind) means `removePlant` plus a `decayed` event: it leaves nothing.
- Every other kind turns into a Dead Plant, as today. A primed Blastberry still explodes.
- Dead Plants are no longer skipped by the phase.

### 3e. Player predictions

- `sim/decay.ts` `wouldDecayWithin(plot, p, seconds)` = timer ≤ seconds **and** `minimumMet` now.
- Use it in:
  - `player.ts` `decaysBeforeNextSession` (`beforeDecay`, `harvestBeforeDecay`, saving a hybrid kept input);
  - `flow/triggers.ts` `decayImminent`;
  - the red decay tone in `SimTooltip`.
- Export a pure, read-only `decayStatus(plot, p)` → `{timesMutated, mutatesRemaining, pooled, combined, minimumMet}` from `index.ts` for the UI. Its name doesn't start with tick or step, so it passes the scope guard.

### 3f. Config and UI

- `config.ts`:
  - `decayExtensionHours` (24, `verified`)
  - `mutationCreditOrder` (`model`)
  - `minimumMutationsOverrides: Record<string, number | "infinite" | "none">`, an empty map
  - Rewrite the descriptions of `harvestWindowCycles` ("timer only; the minimum still applies") and `decayDaysOverrides` (any kind).
- Advanced panel (`ScenarioPanels.tsx`): a **per-kind table** with a decay-days override and a minimum override. Follow the `rareDropValues` editor pattern at about line 321. This is the first UI for `decayDaysOverrides`.
- `SimTooltip` `PlantDetails`:
  - Rows "Times mutated", "Mutates remaining", and "Pool: combined N (pooled)" / "not pooled (hasn't helped yet)" / "not pooled (still growing)".
  - The Decay row becomes "timer in X; then decays" or "timer in X; then +24h (minimum not met)".
- `format.ts`: `decayExtended`. Add it to `NOISY` in `useSimulation.ts` only if it floods the log in practice.
- `PlotView.tsx`: an optional `extended` mark.
- `ReportPanels.tsx`: an "extended 24h" count in the outcomes list.

### 3g. Tests

## Phase 4: "Sanity Check" inspector (simulator)

This mirrors the new Plant Diagnostics Tool ability. Depends on Phase 2 (dry rules). Phase 3 is optional.

- Engine: a new pure `analysis/sanityCheck.ts`: `sanityCheck(state, data, plotId, row, col)`. It reuses `locationOpenFor`, `ringCounts`, `effectiveWeight`, `applyMutationChanceBonus` and the effect simulation (for Godseed).
  - It returns a list in data.json order (**not ranked**).
  - **Can spawn here now** gives each mutation's chance per roll: its weight over `max(blankFillTo, Σw)`.
  - **Can't** gives the missing requirements (with counts), the wrong ground cells, and whether the footprint doesn't fit or is occupied.
  - Candidates: `candidateMutations` for the kinds on the plot, plus the slot's target.
  - It uses no RNG and never mutates the state.
  - The name passes the scope guard.
- Expose it on the engine (`engine.sanityCheck`) or as a pure export from `index.ts`. It runs on the main thread from `snapshot.state`.
- UI: a "Sanity Check" toggle on the plot view. When it is on, hovering an empty cell (or a slot) shows the result in a `SimTooltip` variant (`kind: "check"`). Slots keep their current card, with the check result appended.
- Tests: `analysis/sanityCheck.test.ts`. The result must agree with what `phaseSpawn` would roll: the same weights, and the same Lonelily and dry-neighbour rules.

## Known consequences to expect

- **Uneven aging under ring order.** With the default credit order, extra requirement crops beyond the required count are never credited. They never join a pool and never decay (their own 12 stays positive). `mostRemainingFirst` would make a ring age together instead.
- **Flora removes the base-crop effect.** With Flora at its default of 10, base crops no longer change cycle length or yield. Set Flora lower to study the unique crop bonus.
- **Stoplight Petal** is N/A (timer-only) but is an input for Timestalk, so placed Petals still decay on the timer alone.
- **Witherbloom farms** now consume dead plants: placed ones decay after helping 10 times and must be re-placed from stock.
- **Zombud farms don't change:** their dead plants never decay. Each harvest converts them into Zombud mobs (1 Zombud each) and they are re-placed fresh, as today.
  - Edge case: on a plot where one dead plant feeds both a Witherbloom slot and a Zombud ring, Witherbloom spawns can use up the shared dead-plant pool. That dead plant can then decay before the Zombud is harvested. The player re-places it at the next session, and the Zombud harvest fills any empty ring cell from stock anyway, so the Zombud yield is unaffected.
- **Many expected numbers change.** Decay-dependent tests move to `TIMER_ONLY` or get new expectations. Seed-searching tests may need new seeds where water deaths used to free cells.
